What we found

Business-friendly root causes — without exposing internals.

Timesheets are analytic first

A timesheet creates an Analytic Item. It does not automatically create a Financial Account / Journal Item.

Labor Accrual was not on production

The meeting path “timesheet → journal” required modules that existed in source but were not deployed on production.

Include in Payroll could reset

Project onchange could clear eligibility unintentionally; opt-out projects must remain explicit.

Old lines had multiple causes

Anomalous hours, zero cost, payroll false, missing JE, or source timesheet with no GL by design.

Journal Items alone are incomplete

Timesheets without GL never appear as AMLs; the statement must be Analytic-line primary.

Safety needed company + hours guards

Wrong company configuration and >24h day totals must not silently enter accrual.

What we changed

Implemented and validated on the isolated test database only.

Include in Payroll logic

Preserve eligibility; explicit project opt-out only.

Labor Accrual flow

Populate → draft JE → post, with debit analytic / credit clearing.

period_key / date sync

Batch period keys stay aligned with start/end dates.

AAL-primary statement

Timesheet / no GL + JE-backed rows; no AML duplicates.

Historical remediation workflow

Retro batches proven on clone for valid old periods.

Multi-company guards

Labor accounts/journal must belong to the batch company.

>24h anomaly guard

Exclude single-line and cumulative same-day anomalies; never delete hours.

XLSX template styling

RTL, Arabic headers, existing columns only — STYLE ONLY.
